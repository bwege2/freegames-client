# DCSS 0.34.1: how the port is made and checked

Reference: `crawl-0.34.1.tar.gz`, GitHub's archive of tag `0.34.1`, sha-256
`a48c03653d349cdd185c750f0ff828cdf043c695a829278a30d2edb29fb82eee` (`fetch.sh`). The tarball has no
submodules; the oracle clone (`oracle/build.sh`) adds the original's contrib Lua/SQLite/PCRE/zlib and
builds the console program with GCC.

## What the port is

The whole original is 434,000 lines of C++ and its Lua data. This round ports a tested core by hand:
the character-creation tables and formulas of `species.cc`, `jobs.cc`, `skills.cc`, `ng-setup.cc`,
`player.cc`; the turn/combat formulas of `attack.cc`, `fight.cc`, `melee-attack.cc`; spell data and
`raw_spell_fail` from `spl-cast.cc`/`spl-data.h`; item data from `item-prop.cc`; the branch schedule of
`branch-data.h`; monster data from `dat/mons/*.yaml` and `mon-pick-data.h`; descriptions from
`dat/descript/`; the first tutorial map from `dat/des/tutorial/lesson1.des`.

**The translator.** `re/brogue/tools/c2ts` translates C from clang's syntax trees; its own README says it
handles C. DCSS is C++ with templates, `std::vector`, `std::string`, classes and Lua vaults, so the
Brogue pipeline cannot translate it unchanged. Extending it to the 434,000 lines was not a one-round
job; this port instead reads the data mechanically (`tools/extract.py`: the YAML, the generated
`mon-data.h`/`species-data.h`/`mon-pick-data.h` headers, `spl-data.h`, `item-prop.cc`, `branch-data.h`,
`dat/descript/`) and writes the core by hand from the named functions. The result is therefore a
faithful **core**, not a statement-by-statement translation; `web/games/crawl/README.md` says what is
missing.

`tools/extract.py` writes `web/games/crawl/src/data/*.json`; it is deterministic and can be rerun after
`fetch.sh` and a build (the generated headers need the original's `-builddb`; `oracle/build.sh` does
it). The original's texts are kept verbatim apart from HTML-like markup stripping for the tutorial.

## Oracle and comparisons

- `oracle/build.sh` builds `crawl` (console) and runs `-builddb`.
- `oracle/playable.sh` writes `-playable-json`.
- `oracle/characters.py` starts the original under tmux for 96 species/background pairs (`-seed 7`,
  `-name Test`, weapon `a` when the original offers one), removes the saves between runs, waits for the
  sheet and records HP/MP/AC/EV/SH/Str/Int/Dex/title. It writes
  `web/games/crawl/test/golden/characters.json`.
- `oracle/start.py` records the first D:1 screen of a Human Fighter (messages and HUD) for
  `test/golden/start.json`; `test/start.test.ts` compares the port's first screen with it.
- The RNG golden (`test/rng.test.ts`) is from a C++ program built from `pcg.cc`; it checks the stream
  `random2(100)` for seed 7.

The original's dungeon layouts are generated by C++ (`dgn-layouts.cc`, `dungeon.cc`) and Lua vaults;
the port's generator is its own. The test therefore checks the original's **branch schedule**
(`branch-data.h`), **population tables** and **data**, and the port's own determinism/connectivity, not
the original's map cells. A map-for-map comparison is the next big step if the layout/Lua machinery is
ported.

## Findings worth keeping

- The original's `-playable-json` is the authority for which species/background combinations exist; a
  Draconian is one species with colours, and the port offers the colours as the original's list does.
- Starting stats are deterministic (species + job), not rolled. `aptitudes:` in the species YAML also
  carries `xp`, `hp`, `mp_mod` and `wl`; the first extractor read them from the top level and was fixed.
- `reassess_starting_skills` turns job skill levels into human-aptitude points and recomputes the
  levels with species aptitudes. A character that cannot wear body armour (`MUT_NO_ARMOUR`,
  `MUT_FORMLESS`, Octopode, or a size that cannot wear it) has its Armour points moved to Dodging; this
  is why a Spriggan/Felid Fighter is titled Ducker.
- `base_ac_from` applies a -40% multiplier to body armour for `MUT_DEFORMED`/`MUT_PSEUDOPODS`; Naga and
  Armataur need it, and Naga's racial AC is `100 * XL / 3`.
- Large characters get a robe instead of scale mail and a kite shield instead of a buckler (unless
  they have a small torso); Octopodes/Felids wear no body armour; Poltergeists get a +1 cloak.
- `best_skill` uses `skill(sk, 10, true)` (level*10 + progress) and the skill-order tie-break. The
  port reproduces most titles; three starting characters still differ (Human Enchanter, Tengu Earth
  Elementalist, Octopode Fighter) because the original's exact starting skill points differ by a few
  points from `skill_exp_needed(level, SP_HUMAN) + 1` in ways not yet pinned down.
- The original's `armour_class()` uses `div_rand_round`, so a fraction of an AC can round up on some
  frames; the port uses floor for the sheet and the original's formulas for the rest.
- A monster is `hd`, `hp_10x / 10`, `ac`, `ev`, `exp`, attacks `{type, flavour, damage}` and a spell set
  (`mon-spell.h`); the population is `{min, max, weight, FLAT/PEAK/FALL/SEMI/RISE, MONS_*}` per branch.
