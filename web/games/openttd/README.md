# OpenTTD 15.3: a playable first slice

This folder is the browser port of OpenTTD 15.3. The world generator now
matches the original for **all four climates, variety 0–3, rivers 0–3 and
trees**: TerraGenesis, the climate post-processing, the generated tile loop,
the river builder and tree generation/growth all run natively in TypeScript,
and the map is drawn with the original OpenGFX sprites.

## What is here

* `src/sim/` — the deterministic core and map generator:
  * `random.ts` — OpenTTD's `Randomizer`, `RandomRange` and `Chance16`,
    exactly.
  * `date.ts` — the 74-tick day and the Gregorian calendar from
    `src/timer/timer_game_common.cpp`.
  * `tgp.ts` — TerraGenesis Perlin (`src/tgp.cpp`): the height map,
    frequencies and amplitudes, water level, coastlines, slope smoothing,
    the sine redistribution and the optional curve maps.
  * `landscape.ts`, `world.ts` — `InitializeLandscape`, `FixSlopes`, the
    water conversion, snow/desert/rainforest post-processing, the tile loop
    (`TileLoop_Clear`, `TileLoop_Water`) and `GenerateClearTile`, plus the
    tile accessors and slope helpers.
  * `rivers.ts` — `CreateRivers` and the whole river path: spring search,
    downhill flow, lakes and wetlands, the YAPF river builder with its A*
    heap, river widening and `CmdTerraformLand` on the generated map.
  * `trees.ts` — `GenerateTrees` with the original and improved placers
    (star-shaped groves, same-height trees, rainforest extra trees), the tree
    tile fields, and `TileLoop_Trees` growth/spread during the generated
    0x500 tile-loop ticks.
  * `worldgen.ts` — the new-game order of `src/genworld.cpp`: one
    `StartupEconomy` random draw, landscape (including rivers), the final
    0x500 tile-loop ticks.
* `src/render/` — the WebGL2 palette renderer (`renderer.ts`), the palette
  and its animated ranges (`palette.ts`), the ground sprite selection of
  `src/clear_cmd.cpp` / `src/water_cmd.cpp` (`scene.ts`), and the tree sprite
  selection (`tree.ts`, `treetable.ts` generated from `src/table/tree_land.h`).
* `src/game.ts`, `src/index.ts` — the page, input and the `start(host, ctx)`
  entry point.
* `assets/` — the OpenGFX and OpenTTD sprites converted losslessly to 8bpp
  index atlases (`assets/sprites/`), the DOS palette (`palette.json`) and
  the build manifest. `re/openttd/tools/` has the GRF extractor, the oracle
  and the tests' fixture generator.

## Controls

| Input | Action |
| --- | --- |
| Drag with the mouse, or the arrow keys | Scroll the map |
| Mouse wheel, `+` / `-`, F5 / F6 | Zoom (out 8×, 4×, 2×, normal, in 2×) |
| `N` | Generate a new landscape from a random seed |
| `Home` | Centre the map |
| Save / Load | Write the slice to server storage or restore it |
| Click a town or industry | Show its original name, production, acceptance and cargo data |
| Toolbar: Road / Truck stop / Demolish | Build roads and stops, or remove them; prices are deducted from the balance |
| Click a truck stop | Its panel has “Buy Balogh Coal Truck” |
| Click the truck, then two truck stops | Set the A→B order; “Clear orders” removes it |

The page generates a temperate 256×256 map with the original defaults:
terrain type 1, smoothness 1, variety 0, no sea/lakes, two rivers and the
improved tree placer. On the fixed start seed it adds the 5a scenario: the
town of Barton, a coal mine and a power station, all on verified flat land.
Town/industry placement is a documented simplification (see below); the
cargo and industry numbers are the original tables.

## Reference and tests

The reference is the pinned OpenTTD 15.3 release (see `re/openttd/NOTES.md`
and `web/games/openttd/LICENSE.md`). Fixtures are generated by a dedicated
15.3 build with `re/openttd/oracle/stages.patch`, which can stop after the
landscape (or add towns, industries, objects or trees one at a time); see
`re/openttd/oracle/README.md`. `re/openttd/tools/oracle.mjs` drives the
binary and `re/openttd/tools/fixture.mjs` turns a savegame into the base64
tile arrays in `test/fixtures/`.

The map-generation test compares every tile of the older seeds outside the
not-yet-ported town, industry, object and tree stages: heights, types,
ground bytes (m5) and owner/water bytes (m1) match byte for byte (63,000+
tiles per seed). The river tests compare **every tile with no mask at all**:
height, type (including the tropic zone), `m1`, `m3`, `m4` and `m5`, for

* temperate seed 12345 with 2 rivers,
* tropic seed 12345 with 2 rivers,
* temperate seed 2 with 3 rivers,
* temperate and tropic seed 12345 with trees (all tile bytes, including the
  tree `m2` ground/density word),
* temperate seed 12345 with rivers and trees together,

and the same climates and seeds were compared during development for
variety 1–3. The tree fixtures set `extra_tree_placement = 3`; with the
default `2` the game can grow or spread a handful of trees between map
generation and the save, which is not part of the generator. The sprite test checks the extractor's counts and geometry and
re-decodes sprites from the pinned GRFs when `re/openttd/orig/` is present.

```sh
cd re/openttd
./fetch.sh
./tools/fetch-binary.sh
cd ../../web
npm test
```

## 5c the earning coal truck

The Balogh Coal Truck uses the original engine data:
`ROV(1, 108, 90, ..., 96, 20, 38, 12)` (`src/table/engines.h`).

| Value | Original calculation |
| --- | --- |
| Purchase | `14000 × 108 >> 8` = **£5,906** (`PR_BUILD_VEHICLE_ROAD`) |
| Running | `1600 × 90 >> 8` = **£562/year** (`PR_RUNNING_ROADVEH`) |
| Speed | 96 km/h |
| Capacity | 20 t of coal |

Coal payment uses `GetTransportedGoodsIncome`'s fast-transit branch,
`dist × 255 × units × 5916 >> 21`, with the original coal initial payment
5916 and transit periods 7/255. The mine→power station route is 5 tiles, so a
full 20 t load pays **£71**. Running costs are charged per game day while
moving. The mine stop starts with 20 t of coal and produces at the original
15/month; its station rating (100 adjacent, falling to 0 at 5 tiles) scales
what is available. The power station accepts coal only from a stop within its
four-tile catchment.

The truck uses the original road-vehicle sprite (`0xCDC`), moves along the
built roads with a four-directional BFS (no diagonal shortcuts), ramps up
with a linear acceleration approximation to 96 km/h, loads/unloads with a
short dwell and automatically repeats A→B→A. Time is simplified to one game
day per real second. To give 5c a working route, the 5a power station is now
placed six or more tiles from the coal mine with a flat, clear L-shaped road
corridor between them; the town and industry placement remain simplified and
deterministic.

The live panel shows cargo, speed, orders, trips, revenue, running costs and
profit; the fleet panel shows the balance and totals. `test/vehicles.test.ts`
checks the original prices/payment, four-way pathfinding, catchment, and a
complete load→deliver→return simulation.

## 5b construction

The toolbar builds roads and truck stops and demolishes them. Prices are the
original price bases from `src/table/pricebase.h`:

| Action | Price |
| --- | --- |
| Build one road tile | £95 (`PR_BUILD_ROAD`) |
| Clear one road tile | £40 (`PR_CLEAR_ROAD`) |
| Build a truck stop | £200 (`PR_BUILD_STATION_TRUCK`) |
| Clear a truck stop | £50 (`PR_CLEAR_STATION_TRUCK`) |

The player starts with £100,000. Roads need flat, clear land; water, slopes,
trees, town houses, industries and existing stops are occupied and refused.
Town roads from the 5a scenario are free to connect to and cannot be
demolished. A truck stop is one tile, needs an adjacent road, and takes the
original ground and building sprites (`SPR_TRUCK_STOP_*`, 2708–2715) with its
orientation and a four-tile catchment label. Road drags build an L-shaped run
(x first, then y); every tile is charged and checked separately.

## 5a scenario data

* Town: Barton, built from the original English name parts
  (`_name_original_english_2/3/4/5` in `src/table/townname.h`), 12 houses and
  a 5×5 road cross. Accepts passengers and mail, as the original towns do.
* Coal Mine: produces coal at the original rate 15
  (`src/table/build_industry.h`, `MI(_tile_table_coal_mine, ...)`).
* Power Station: accepts coal with the original input multiplier 256; its
  coal-accepting tile has 8/8 acceptance (`_origin_industry_tile_specs`).
* Coal cargo: bit 1, initial payment 5916, transit periods 7/255, weight 16
  (`src/table/cargo_const.h`).
* Sprites: `SPR_BUILD_TOWNHOUSE_06_V1` (1446), `SPR_ROAD_X` (1333),
  `SPR_IT_POWER_PLANT_TRANSFORMERS` (2054) and the neighbouring original
  industry sprite 2050. All are present in the OpenGFX atlas.

Placement is simplified: the scenario scans the generated map for flat,
clear footprints and draws one original building sprite per industry at its
north tile, instead of running the full town/industry generator and
multi-tile layouts. This is deterministic and verified by
`test/scenario.test.ts`. The next milestone, 5b, adds road construction and
two truck stops.

## Saves and listing

The toolbar's **Save** button writes `openttd-save.json` to `ctx.storage`; **Load** restores it. The JSON contains the seed, camera, roads, stops, money, fleet stock/time, truck path/position/orders/cargo/trips and the running/revenue counters. A missing or corrupt save is reported in the status line and leaves the current game untouched. The game also saves on `pagehide` and when leaving. `test/save.test.ts` does an exact JSON round trip and then ticks both copies to check they stay identical.

The game is now listed (`"listed": true`, `"added": "2026-11-24"`). It is a **playable slice**, not the whole OpenTTD.

## Deliberate limits of this slice

* Only one simplified town/industry scenario exists; the full town and
  industry generators are not implemented. The industries are single
  sprites, roads are built as L-shaped runs, cargo is only coal, time runs at
  one game day per real second, acceleration is a linear approximation, and
  only the Balogh Coal Truck exists. There are no trains, buses, depots,
  signals, airports, ships, industries beyond coal, town growth, competitor
  companies, online play, sound or music. The full OpenTTD map/economy is
  not claimed. The 5a industries are
  single-sprite representations of their original multi-tile layouts.
  Objects (lighthouses, transmitters), rail, stations, road vehicles,
  pathfinding and the full economy are still missing.
* Tree growth and spread after the map has started are not ticked yet; only
  the generation tile loop is simulated. The renderer draws all ground first
  and then trees back to front per tile, not with the original's full
  viewport sprite sorter.
* The renderer draws ground sprites only. Slopes use the original's 8bpp
  sprites; above-normal zoom uses the GRF's 2× sprite when it exists and
  otherwise scales the normal one. This is not yet the original's full
  viewport sorter (there are no multi-tile buildings or vehicles to sort).
* Sound and music are not played yet; the OpenSFX/OpenMSX files are pinned
  but not used.
* Only Temperate is generated by the page. The map generator itself is
  oracle-tested for all four climates.
* The map is not saved yet; the game does not connect to the server.
* The renderer is checked at the sprite and tile level (geometry, source
  hashes, the ground/water bytes). A pixel comparison with the original's
  own screenshot is not in the tests yet: the released Linux binary has no
  screenshot provider without a video backend here.

Everything above is a limit of this stage, not a claim about the finished
port.
