# Dungeon Crawl Stone Soup (0.34.1)

A port of the tested core of **Dungeon Crawl Stone Soup 0.34.1** (the latest stable release, 15 March
2026) to TypeScript in the browser. One character goes into the Dungeon, fights, finds things, learns
spells, takes the stairs, and may die for good; saves, morgue files and the high-score list live in the
player's account storage.

Reference: **DCSS 0.34.1**, GitHub tag `0.34.1`; `re/crawl/fetch.sh` downloads
`crawl-0.34.1.tar.gz` (sha-256 `a48c03653d349cdd185c750f0ff828cdf043c695a829278a30d2edb29fb82eee`) and
unpacks it into `re/crawl/orig/` (never committed). `re/crawl/oracle/build.sh` builds the console program
for the comparisons; `re/crawl/tools/extract.py` converts its data. What is original and what the port
does is in `LICENSE.md`.

## What works

- **Character creation** for all 35 playable species and 26 backgrounds of 0.34.1: the original's
  starting stats, aptitudes, mutations, hit points, magic points, AC/EV/SH, titles, equipment, starting
  skills and spell library (the first level-1 spell is memorised, as in `ng-setup.cc`). The combinations
  are the original's `-playable-json` list; a Draconian's colour is chosen at creation.
- **The Dungeon and its branches**: D:1-15, the Ecumenical Temple, the Lair of Beasts, the Orcish Mines,
  the Elven Halls, the Vaults, the Depths, the Swamp/Shoals/Snake Pit/Spider Nest, the Slime Pits, the
  Crypt and the five levels of Zot. The branch depths come from `branch-data.h`; the monster tables are
  `mon-pick-data.h`'s (Dungeon, Lair, Orc, Elf, Vaults, Depths, Zot and the Lair branches). The Orb of
  Zot is on Zot:5; carrying it back to D:1 and taking the exit wins.
- **Play**: 80x70 levels of rooms and corridors with pools, trees and altars; a 35x17 viewport and the
  original's 80x24 console HUD; field of view; movement and running; doors; up/down stairs and branch
  entrances; melee attacks with the original's to-hit and damage formulas, AC/EV/GDR, brands and
  monster attacks; monster waking, chasing, fleeing, spellcasting and speech-free messages; item
  generation, inventory, equipment, potions, scrolls, wands, spell memorisation and casting, XP,
  levels, skills and training; auto-explore, look, rest; death; save/load; morgue files; a personal
  high-score list in account storage.
- **Gods**: the altars of the Ecumenical Temple and the Dungeon can be prayed at (`p`); Trog, Okawaru,
  Makhleb, Sif Muna, Vehumet and Elyvilon have their `ability.cc` invocation costs, failure chances,
  piety conduct and effects (`a`). Piety uses religion.cc's 30/50/75/100/120/160 breakpoints and the
  gain/taper rules; a Berserker starts with Trog at 35 piety (ng-setup.cc).
- **Traps and shops**: the 0.34 trap types of `trap-type.h` and `traps.cc` (teleport, permanent
  teleport, dispersal, shaft, alarm, net, web, Zot, tyrant, archmage, harlequin, devourer, pressure
  plate, Golubria), their placement rates and effects; shops with `shopping.cc` values, greed,
  stock sizes and prices and a buy menu.
- **Ranged combat**: `ranged-attack.cc`/`attack.cc` to-hit and damage for the 0.34 launchers (sling,
  shortbow, orcbow, longbow, arbalest, triple crossbow, hand cannon) and `throw.cc`/`fight.cc`
  throwing for darts, stones, large rocks, javelins and boomerangs, with ammo destruction and javelin
  penetration.
- **Identification and books**: per-game potion colours, wand materials, jewellery appearances and
  scroll labels (item-name.cc `make_name`), type identification (`scroll of identify`, using an item),
  and the 69 fixed spellbooks of `book-data.h`; `book of ...` spells can be memorised.
- **Mutations**: mutation-data.h's 213 mutations with their weights, levels and messages; `potion of
  mutation` follows potion.cc's remove-2-3/add-1-3/good-chance sequence, and the stat mutations are
  exact.
- **Tutorial**: the first lesson's original map (`dat/des/tutorial/lesson1.des`), its marker messages
  and the exit. The later lessons are not ported.
- **Tests** in `test/`: data against the original's headers, the PCG/RNG values against the original's
  `pcg.cc` program, 97 character sheets generated by the original (see below), determinism and
  connectivity of levels, the branch schedule, the Orb, save round trips, and headless sessions
  (creation, fight, stairs, potion, save/load, death, tutorial), plus the god, trap, shop, ranged,
  appearance, spell and mutation tables (174 tests). `npm test` runs them.

## Checked against the original

- `test/golden/characters.json` is from `re/crawl/oracle/characters.py`: 97 species/background
  combinations run in DCSS 0.34.1 itself (tmux, seed 7, weapon choice `a`), recording the sheet the
  original showed on D:1. `test/characters.test.ts` builds the same characters and compares HP, MP,
  Str/Int/Dex, AC/EV/SH and titles. Of the 95 non-Wanderer sheets, 92 match every checked value; Oni's
  EV differs by one point (the large-shield penalty) and two titles differ in a tie-break (Human
  Enchanter, Tengu Earth Elementalist). The 96th entry is the original's random Wanderer, which the port
  does not reproduce.
- `test/start.test.ts` compares the first screen (the four messages and the HUD values of a Human
  Fighter, seed 7) with `re/crawl/oracle/start.py`'s capture `test/golden/start.json`; the map is not
  compared.
- `test/rng.test.ts` checks the PCG32 stream against a C++ program built from the original's `pcg.cc`
  (seed 7: 38, 21, 97, …).
- `test/data.test.ts` checks species/job/monster/item/spell values against the original's YAML and
  headers (e.g. the rat's 1 HD, 2.5 HP, 10 EV and bite 3; the long sword's 10 damage; scale mail's 6 AC
  and -100 EV; Magic Dart's level 1 and 8 range; the Dungeon population's weights and depth ranges).
- `test/traps.test.ts`, `test/shops.test.ts`, `test/ranged.test.ts`, `test/appearance.test.ts`,
  `test/spells.test.ts` and `test/mutations.test.ts` check the values against the original's files
  named in each test (`traps.cc`, `shopping.cc`, `zap-data.h`, `item-name.cc`, `mutation-data.h`, ...).
  These are source comparisons, not runs of the original binary; no binary comparison of these
  mechanics exists yet.
- **Dungeon layouts are not compared with the original, and do not match it.** The original's path is
  `builder()` -> `_build_dungeon_level()` -> `_builder_normal()`, which picks a `layout` vault; the
  layouts are Lua (`dat/dlua/layout/*.lua`, 6,914 lines, plus `dat/des/builder/*.des`) and vaults are
  197,022 lines of `.des` with Lua; `dungeon.cc` is 7,771 lines and then places stairs, branch
  entrances, vaults, monsters, items and traps. The port has no Lua VM, no `.des` vault loader and no
  port of that pipeline, and the porting rules forbid an Emscripten/WASM build of the original. The
  port therefore keeps its own rooms-and-corridors generator (pools, trees, altars, traps, a shop and
  one Orb room). The branch schedule, population, monster and item data are the original's. No
  tile-for-tile map golden exists; producing one would require porting `dungeon.cc`, `dgn-layouts.cc`,
  the Lua layout/vault library and the `.des` loader, which is far beyond this round.

## Deviations the browser and the scope force

- **Not the whole game.** Portals and portal vaults, most vaults and special levels, most monsters'
  special abilities, most spells, and many mutations' effects are missing or simplified.
- **Dungeon layouts** are the port's own rooms-and-corridors generator (pools, trees, altars, traps, a
  shop, one Orb room); they are not the original's levels for the seed. Branch entrance depths are the
  original's ranges, chosen once per game. See the last bullet of the comparison section for why.
- **Gods**: only six of the 23 gods are implemented (Trog, Okawaru, Makhleb, Sif Muna, Vehumet,
  Elyvilon). Their altars work, but there are no god gifts, no wrath/penance beyond losing the god, no
  divine passives other than Vehumet's spell failure/range and Makhleb's healing (and Trog's added
  rage), and summon durations are not tracked. Makhleb's Destruction is a straight beam rather than the
  original's bolt/explosion geometry; Infernal Servant uses the original's servant table but not its
  full `monster_picker` fallbacks. The other gods' altars say they are not implemented.
- **Traps**: types, placement rates and the common effects are the original's; tyrant/archmage/
  harlequin traps only show their messages (no monster buffs), Zot traps implement a subset of the
  weighted effects, shafts always drop one level (the original can drop more), and corrosion is not
  modelled.
- **Shops**: prices, greed, stock classes and stock sizes are the original's, but shop *placement* is
  the port's own (the original places shops from vaults), and there are no keepers, no
  identified/unknown-stock distinction in the menu beyond the shop type, and no shop doors.
- **Ranged combat**: 0.34 launchers are fired without ammunition (that is the original's rule), but
  throwing nets are not generated, the original's quiver/targeting UI is replaced by a direction
  prompt, and monster ranged attacks are not implemented.
- **Spells**: only `IMPLEMENTED_SPELLS` in `src/game/magic.ts` have effects, and those use the
  `zap-data.h` damage dice. Every other spell refuses with "That spell is not implemented in this
  port." instead of faking an effect. Monster spell effects remain the port's simplified ones.
- **Identification**: potion/wand/jewellery/scroll appearances are the original's strings and the
  scroll labels use the original's `make_name`; the appearance assignment uses the port's RNG stream
  and is per player, not the original's `you.item_description` sequence. Books are always known, there
  are no artefacts/randarts, and only `scroll of identify` and use-identification teach types.
- **Mutations**: the table, weights, levels and messages are mutation-data.h's, and `potion of
  mutation` follows the original's sequence; only the stat mutations (strong/clever/agile), the
  HP/AC/EV/regen mutations already in `player.ts`, and mutation levels are modelled. Most of the 213
  mutations' effects are not.
- **Tutorial**: lessons 2-5 (monsters, items, magic, gods) are not ported.
- **Wanderer** is a random kit of the port's own (the original's Wanderer generation is not
  reproduced); the character-sheet comparison skips it.
- **Files.** A save is the port's gzip-compressed JSON in account storage (`savegame`), not the original's binary save
  format; morgue files are text in account storage (`morgue-*.txt`); the high-score list is the
  account's `scores.json` (a personal list), not the machine-wide `scores` file. The storage limits
  apply (512 KiB per file, 4 MiB in total).
- **Leaving the page** saves the current game when the page lets the request through; a game saved with
  `S` is written before leaving. The browser page cannot keep the game running after it is left.
- **Screen and keys.** The game fills the page with its 80x24 screen; there is no tiles mode, no mouse
  and no sound. A terminal's arrow keys and the original's vi keys work; the browser's F5/F11/F12 and
  copy/paste stay with the page. `Ctrl+W`/`Ctrl+T`/`Ctrl+N` are the browser's; the port does not use
  them. The title screen and a `Q` confirmation are the port's.
- **Death/quit** show the original's death text and a summary, then return to the game page; Play starts
  a new character (or continues a save).

## Controls

`?` in the game lists them. The original's keys:

| Keys | What |
| --- | --- |
| `h j k l y u b n`, arrow keys, `1`-`9` | move or attack |
| `H J K L Y U B N` | run |
| `.` `s` `5` | wait a turn |
| `g` `,` | pick up |
| `i` | inventory |
| `e` `w` | wield/wear/put on |
| `c` | take off |
| `d` | drop |
| `q` `r` `z` `M` `V` | quaff, read, cast, memorise, zap a wand |
| `f` `t` | fire a launcher / throw a missile |
| `p` `a` | pray at an altar / use a divine ability |
| `>` `<` | stairs down/up or a branch entrance |
| `o` `R` `x` | auto-explore, rest, look |
| `m` `C` `@` `?` | skills, character sheet, character sheet, help |
| `S` `Q` | save and leave; quit without saving |

## Building and running

```sh
re/crawl/fetch.sh                         # the reference source (not committed)
python3 re/crawl/tools/extract.py         # src/data/*.json from it (needs PyYAML and a built tree)
cd web && npm ci && npm test              # the port's tests (node --test)
npm run build                             # tsc --noEmit + vite + legal/seo/downloads
node web/scripts/screenshots.mjs crawl    # needs the built site and server/target/freegames-server.jar
```

The oracle (optional) needs git, gcc/g++ and ncurses headers, or a Nix GCC wrapper:

```sh
re/crawl/oracle/build.sh                  # clones the tag with its contrib submodules and builds the console
re/crawl/oracle/playable.sh               # -playable-json
python3 re/crawl/oracle/characters.py     # the 97 sheets in test/golden/characters.json (needs tmux)
```

`re/crawl/NOTES.md` has the details of the extraction and the comparisons.
